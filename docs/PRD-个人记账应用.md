## 1. 项目背景与目标

### 1.1 背景

市面上主流记账 App 普遍存在三类问题：一是强制注册登录、数据上传云端，隐私顾虑大；二是功能堆砌（理财、贷款、社区），核心的「记一笔」路径被埋在多层菜单里；三是导出能力弱，用户被锁死在平台里，数据不属于自己。

本项目要做的是**反方向的减法产品**：打开即用、三秒记一笔、数据完全留在本机、随时能完整导出。

### 1.2 产品目标

1. **极速录入**：从打开页面到完成一笔记录 ≤ 5 秒，主流程键盘可完成。
2. **一目了然**：进入首页即看到本月收支结余与结构占比，无需点击。
3. **数据自主**：全部数据存本地，支持一键导出 CSV / JSON，可随时迁移。
4. **零门槛**：无需注册、无需联网、无需安装。

### 1.3 非目标（明确不做）

- 不做账号体系与云端同步（一期）
- 不做理财、投资、借贷、社区等扩展模块
- 不做多人协作与账本共享
- 不做票据 OCR 识别

## 4. 详细功能需求

### 4.1 记账核心（P0）

**FR-1.1 新增账单**

- 必填字段：类型（支出/收入）、金额、分类、日期
- 选填字段：备注（≤ 100 字）、账户、标签
- 金额输入规则：
  - 仅允许最多两位小数；禁止负数、0、非数字
  - 输入时实时千分位格式化
  - 支持简单算式（如 `28+15` 自动求和）—— P1
- 交互要求：
  - 默认日期为今天，默认类型为「支出」
  - 分类以九宫格图标形式展示，常用分类置顶（按近 30 天使用频次排序）
  - 保存后 Toast 提示「已记录」，表单重置但保留类型与账户
  - 连续记账不跳页，支持连续录入多笔

**FR-1.2 编辑 / 删除**

- 列表项左滑（移动端）/ 悬停（桌面端）显示「编辑 / 删除」
- 删除需二次确认，确认后可从 Toast 中「撤销」（5 秒内）
- 编辑后统计与余额即时重算

**FR-1.3 快捷键（桌面端）**

| 按键 | 行为 |
| --- | --- |
| `N` | 打开新增账单 |
| `Esc` | 关闭弹层 |
| `Enter` | 提交表单 |
| `←` `→` | 列表切换上下月 |

**FR-2.1 自定义分类（P1）**

- 可新增一级分类，指定名称、图标（内置图标库）、颜色、所属类型
- 支持顺序拖拽排序、隐藏（不删除，历史账单仍显示）
- 删除分类时，若有关联账单，必须提示「将该分类下 N 笔账单转移到 [选择分类]」

**FR-2.2 标签（P1）**

- 标签为自由文本，全局复用，支持自动补全
- 一笔账单最多 5 个标签
- 标签可与分类交叉筛选（如「出差」+「餐饮」）

---

### 4.3 账户与账本（P1）

**FR-3.1 账户**

- 预置：现金、微信钱包、支付宝、银行卡、信用卡
- 字段：名称、类型、初始余额、图标、颜色、是否计入总资产
- 当前余额 = 初始余额 + Σ收入 − Σ支出 − Σ转出 + Σ转入
- 信用卡账户余额为负数表示欠款，UI 用「待还」展示

**FR-3.2 转账**

- 记录字段：转出账户、转入账户、金额、日期、备注
- 转账不计入收入 / 支出统计，仅影响账户余额
- 转出账户 = 转入账户时禁止提交

---

### 4.4 账单列表（P0）

**FR-4.1 展示**

- 按日期倒序，日期作为分组头，显示当日「支出合计 / 收入合计」
- 每条显示：分类图标、分类名、备注、账户、金额（支出红色 `-`，收入绿色 `+`）
- 月度汇总栏吸顶：本月收入 / 支出 / 结余

> ⚠️ 颜色遵循中文财务习惯：**支出为红、收入为绿**。可在设置中提供「国际配色」切换（P2）。

**FR-4.2 筛选与搜索**

- 搜索：匹配备注、分类名、标签、金额数字
- 筛选条件可组合，且需在 UI 上显示「已启用 N 个条件」，一键清空
- 筛选状态写入 URL Query，刷新后保留，可分享

**FR-4.3 性能要求**

- 5000 条记录下列表滚动保持 60fps（虚拟滚动）
- 筛选 / 搜索响应 ≤ 200ms（本地索引）

### 4.5 统计报表（P0）

**FR-5.1 概览卡**

- 三个数字：本月支出、本月收入、本月结余
- 每项展示环比变化（如「较上月 ↓ 12%」）
- 点击卡片进入对应明细筛选

**FR-5.2 分类占比环形图**

- 默认展示支出 Top 6，其余归入「其他」
- 中心显示总额，图例可点击高亮，点击扇区跳转筛选明细

**FR-5.3 趋势柱状图**

- 近 6 个月收入 / 支出双柱对比，X 轴月份，Y 轴金额
- 悬停显示具体数值与结余
- 支持切换「周 / 月 / 年」粒度

**FR-5.4 分类排行（P1）**

- Top 10 列表，含金额、笔数、占比、环比
- 支持支出 / 收入切换

---

### 4.6 预算管理（P1）

- 支持设置月度总预算、分类预算
- 首页展示进度条：已用 X / 预算 Y（Z%）
- 颜色阈值：< 60% 中性色、60–90% 警示色、> 90% 危险色
- 达到 80% 与 100% 时，在首页顶部展示提醒条
- 预算按自然月重置，历史月份预算保留可查

---

### 4.7 数据管理（P1）

**FR-7.1 导出**

- CSV：UTF-8 with BOM（保证 Excel 中文不乱码），字段含日期、类型、分类、二级分类、金额、账户、标签、备注
- JSON：完整数据快照，含 schema 版本号，用于恢复
- 导出文件名：`ledger-{账本名}-{YYYYMMDD}.csv`

**FR-7.2 导入**

- JSON：校验 schema 版本 → 提示「覆盖 / 合并」→ 执行
- CSV：先解析并展示预览表，逐行校验（日期/金额格式），错误行高亮并允许下载错误报告
- 导入前自动生成一次本地快照，失败可回滚

**FR-7.3 清空数据**

- 需输入「确认清空」四个字方可执行
- 执行前自动导出一份备份文件

---

### 4.8 设置（P1 / P2）

- 主题：浅色 / 深色 / 跟随系统（P1）
- 每月起始日（P2）
- 货币符号（P2）
- 本地密码锁：4–6 位数字，进入需输入，数据本身仍为明文存储（P2，需在文档与 UI 中明确说明其安全边界）

## 5. 数据模型设计

```ts
// schema v1

type TxType = 'expense' | 'income';
type ThemeMode = 'light' | 'dark' | 'system';

interface Category {
  id: string;              // uuid
  name: string;
  type: TxType;
  parentId: string | null; // null = 一级分类
  icon: string;            // 图标 key
  color: string;           // hex
  sort: number;
  hidden: boolean;
  isPreset: boolean;
}

interface Account {
  id: string;
  name: string;
  kind: 'cash' | 'wechat' | 'alipay' | 'debit' | 'credit' | 'other';
  initialBalance: number;  // 分
  icon: string;
  color: string;
  includeInTotal: boolean;
  archived: boolean;
}

interface Tag {
  id: string;
  name: string;
  color?: string;
}

interface Transaction {
  id: string;
  type: TxType;
  amount: number;          // 单位：分（整数，避免浮点误差）
  categoryId: string;
  subCategoryId?: string;
  accountId: string;
  occurredAt: number;      // 时间戳（ms）
  note?: string;
  tagIds: string[];
  createdAt: number;
  updatedAt: number;
}

interface Transfer {
  id: string;
  fromAccountId: string;
  toAccountId: string;
  amount: number;
  occurredAt: number;
  note?: string;
  createdAt: number;
}

interface Budget {
  id: string;
  month: string;           // YYYY-MM
  categoryId: string | null; // null = 总预算
  amount: number;
}

interface Settings {
  theme: ThemeMode;
  currencySymbol: string;
  monthStartDay: number;   // 1-28
  colorScheme: 'cn' | 'intl';
  lockEnabled: boolean;
  lockHash?: string;
}

interface LedgerSnapshot {
  schemaVersion: 1;
  exportedAt: number;
  categories: Category[];
  accounts: Account[];
  tags: Tag[];
  transactions: Transaction[];
  transfers: Transfer[];
  budgets: Budget[];
  settings: Settings;
}
```

**关键约定**

1. **金额统一用「分」存整数**，只在展示层转元，彻底规避 `0.1 + 0.2` 类浮点问题。
2. **时间统一存时间戳**，展示层按 `monthStartDay` 计算归属月份。
3. 所有实体带 `id`（uuid v4），便于导入合并时去重。
4. `schemaVersion` 用于将来迁移，导入时版本不匹配需走迁移函数。

**IndexedDB 表设计（基于 Dexie.js）**

| 表名 | 主键 | 索引 |
| --- | --- | --- |
| transactions | id | occurredAt, categoryId, accountId, type, *tagIds |
| categories | id | type, parentId, sort |
| accounts | id | kind |
| tags | id | name |
| transfers | id | occurredAt, fromAccountId, toAccountId |
| budgets | id | month, categoryId |
| settings | key | — |

## 7. 关键交互流程

### 流程 A：记一笔（核心路径，目标 ≤ 5 秒）

1. 点击悬浮按钮 / 按 `N` → 弹出记账面板（底部抽屉式，移动端从下往上滑出）
2. 默认「支出」Tab 高亮，光标自动聚焦金额输入框，唤起数字键盘
3. 输入金额 → 点击分类图标（常用分类置顶）
4. 选填备注 / 账户 / 标签 / 改日期
5. 点击「保存」→ Toast「已记录 ✓」+「撤销」
6. 面板保留，可继续记下一笔；点击遮罩或 `Esc` 关闭

### 流程 B：查看某分类明细

首页环形图点击「餐饮」扇区 → 跳转账单页 → 自动带上筛选条件（本月 + 支出 + 餐饮）→ 筛选条展示可移除的条件标签。

### 流程 C：导入历史数据

设置 → 数据管理 → 导入 CSV → 选择文件 → 预览解析结果（正确 N 行 / 错误 M 行）→ 确认导入 → 显示进度 → 完成报告（成功 N 条，跳过 M 条）。

## 8. 非功能需求

| 类别 | 要求 |
| --- | --- |
| 性能 | 首屏 LCP < 1.5s（本地无网络依赖）；5000 条记录列表滚动 60fps |
| 兼容性 | Chrome / Edge / Safari / Firefox 最近两个大版本；iOS Safari 15+、Android Chrome 100+ |
| 响应式 | 320px–2560px 全区间可用；移动端优先设计 |
| 离线 | 完全离线可用（PWA + Service Worker，P1） |
| 无障碍 | 键盘可完成全部核心操作；对比度符合 WCAG AA；表单元素带 label |
| 数据安全 | 数据不出本机；无任何埋点与外部请求；导出文件由用户自行保管 |
| 国际化 | 一期仅中文；文案集中管理以便后续扩展 |
| 可维护性 | TypeScript strict 模式；核心计算逻辑（余额、统计）必须有单元测试，覆盖率 ≥ 80% |
| 可访问性告知 | 密码锁为「本地遮罩」，非加密存储，需在 UI 明确说明 |

## 9. 技术方案

| 层 | 选型 | 理由 |
| --- | --- | --- |
| 框架 | React 18 + TypeScript | 生态成熟，类型安全，适合长期迭代 |
| 构建 | Vite | 冷启动快，HMR 体验好 |
| 路由 | React Router v6 | 筛选条件可写入 URL Query |
| 状态管理 | Zustand | 轻量，模板代码少；本地数据的读写分离清晰 |
| 本地存储 | Dexie.js（IndexedDB 封装） | 支持索引查询、事务、大容量数据 |
| 图表 | Recharts 或 ECharts | 环形图 / 柱状图开箱即用；ECharts 更适合中文场景 |
| 样式 | CSS Modules + CSS 变量 | 零运行时开销，主题切换只需改变量 |
| 日期 | dayjs | 体积小，2KB |
| 图标 | lucide-react | 线性风格统一，按需引入 |
| 表单校验 | zod + react-hook-form | schema 与 TS 类型同源，导入校验可复用 |
| 测试 | Vitest + Testing Library | 与 Vite 同体系；核心计算逻辑优先覆盖 |
| 代码规范 | ESLint + Prettier + husky（pre-commit） | 提交前自动校验 |

**建议目录结构**

```
src/
├── app/                 # 路由、全局 Provider、主题
├── components/          # 通用 UI（Button、Modal、AmountInput…）
├── features/
│   ├── transaction/     # 记账：表单、列表、筛选
│   ├── category/
│   ├── account/
│   ├── budget/
│   ├── report/          # 图表与统计
│   └── data/            # 导入导出
├── db/                  # Dexie schema、迁移、仓储层
├── domain/              # 纯函数：金额计算、统计聚合、预算进度
├── hooks/
├── lib/                 # 工具函数、格式化
├── types/
└── styles/
```

**分层原则**：`domain/` 为纯函数，不依赖 React 与 db，便于单元测试；`db/` 只做读写；`features/` 负责编排；`components/` 无业务逻辑。
